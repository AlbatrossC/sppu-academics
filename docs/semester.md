# Semester Mapping Agent Workflow

Use this document when a user asks an AI agent to create semester mapping for a `papers/` path.

The agent must research and stage proposals only. Do not edit `mapping/semester_mapping.yml` or generated manifests directly. The human reviews `changelog/semester.md` first, then chooses whether to apply.

## Scope Rules

- Standard branches use `papers/<branch>/<year>/<pattern>/<subject>`.
- First Year uses `papers/first-year/<pattern>/<subject>`.
- MBA is skipped because semester is already part of its hierarchy.
- Honors is skipped because semester mapping is not used there.
- If the user gives a subject folder, map that subject and include context for sibling subject folders in the same pattern folder.
- If the user gives a pattern/year/branch folder, map every reviewable pattern folder under it.

## Required Local Context

First print or inspect the context payload generated by the local tool. The user may give either a pattern folder or a subject folder:

```bash
python3 tools/semester_mapping.py preview papers/artificial-intelligence-and-data-science/te/2019_pattern
python3 tools/semester_mapping.py preview papers/artificial-intelligence-and-data-science/te/2019_pattern/artificial_nueral_network_aids
```

The payload is created by listing local subject directories. It includes:

- `scope.branch_name`
- `scope.year_name`
- `scope.pattern_name`
- `subjects[].subject_key`
- `subjects[].subject_name`
- `subjects[].directory_name`
- `subjects[].folder`

When the input is a subject folder, `scope.focus_subject_key` and `scope.focus_subject_path` identify the requested subject, while `subjects[]` still lists sibling subject folders in the same pattern folder for context.

Only map subjects present in `subjects[]`.

## Research Requirements

Search the web for the exact SPPU syllabus context:

- `SPPU`
- branch display name
- year display name, such as `SE`, `TE`, `BE`, or `First Year`
- pattern name, such as `2019 Pattern`
- subject display name and directory name

Prefer official or high-confidence syllabus PDFs/pages. Inspect PDFs when available. Use question-paper pages only as secondary evidence when syllabus evidence cannot be found.

Use one of these `semester_no` values:

- a number, such as `5`, when evidence clearly supports a normal semester
- `"other"` when the subject is reviewed and intentionally included, but is not tied to a numbered semester
- `"unresolved"` when evidence is missing, conflicting, or only guessed from convention

## Stage Result Format

After research, write a JSON file in `/tmp` and stage it:

```bash
python3 tools/semester_mapping.py stage /tmp/semester-stage.json
```

Single pattern payload:

```json
{
  "path": "papers/artificial-intelligence-and-data-science/te/2019_pattern",
  "entries": [
    {
      "subject_key": "artificial_nueral_network_aids",
      "subject_name": "Artificial Nueral Network",
      "semester_no": 6,
      "status": "mapped",
      "confidence": "high",
      "evidence": "Artificial Neural Network is listed under Semester VI in the SPPU Third Year AI&DS 2019 Pattern syllabus.",
      "sources": [
        {
          "title": "SPPU TE Artificial Intelligence and Data Science 2019 Pattern Syllabus",
          "url": "https://example.edu/syllabus.pdf"
        }
      ]
    }
  ]
}
```

Reviewed non-numbered subject:

```json
{
  "subject_key": "example_subject_key",
  "subject_name": "Example Subject",
  "semester_no": "other",
  "status": "mapped",
  "confidence": "high",
  "evidence": "Reviewed as intentionally included without a numbered semester.",
  "sources": []
}
```

Unresolved subject:

```json
{
  "subject_key": "example_subject_key",
  "subject_name": "Example Subject",
  "semester_no": "unresolved",
  "status": "unresolved",
  "confidence": "low",
  "evidence": "No clear syllabus evidence was found.",
  "sources": []
}
```

Single subject payload:

```json
{
  "path": "papers/artificial-intelligence-and-data-science/te/2019_pattern/artificial_nueral_network_aids",
  "subject_key": "artificial_nueral_network_aids",
  "subject_name": "Artificial Nueral Network",
  "semester_no": 6,
  "status": "mapped",
  "confidence": "high",
  "evidence": "Artificial Neural Network is listed under Semester VI in the SPPU Third Year AI&DS 2019 Pattern syllabus.",
  "sources": [
    {
      "title": "SPPU TE Artificial Intelligence and Data Science 2019 Pattern Syllabus",
      "url": "https://example.edu/syllabus.pdf"
    }
  ]
}
```

Multi-folder payload:

```json
{
  "reviews": [
    {
      "path": "papers/artificial-intelligence-and-data-science/se/2019_pattern",
      "entries": []
    },
    {
      "path": "papers/artificial-intelligence-and-data-science/te/2019_pattern",
      "entries": []
    }
  ]
}
```

The stage command writes:

```text
changelog/semester.md
```

Review sources and evidence are kept only in the changelog. They are not written to `mapping/semester_mapping.yml` or manifest JSON.

## Human Review Gate

After staging, tell the user to inspect:

```text
changelog/semester.md
```

Ask whether to apply. Do not apply automatically.

If the user approves, run:

```bash
python3 tools/semester_mapping.py apply
```

Apply updates:

- `mapping/semester_mapping.yml`
- generated `manifest/*.json` semester fields

If the user rejects or wants to start over:

```bash
python3 tools/semester_mapping.py discard
```

## Acceptance Checklist

- The changelog is grouped by folder and semester.
- Every staged subject key exists in the local preview payload.
- Every mapped subject has a source URL or clear evidence note.
- Uncertain subjects use `semester_no: "unresolved"`.
- No sources are written to approved YAML or manifests.
