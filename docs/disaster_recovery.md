# Disaster Recovery

This document covers full recovery from a fresh clone or a corrupted local state.

> **Assumption:** Committed mapping files (`mapping/*.json`, `mapping/folder_names.yml`) are present and `.env` has been recreated locally.

---

## Step 1 — Install Dependencies

```bash
python3 -m pip install -r requirements.txt
```

Copy environment templates if they do not exist:

```bash
cp .env.example .env
cp config.example.json config.json
```

Required `.env` keys:

```env
GOOGLE_API_KEY=your_google_api_key
GROQ_API_KEY=your_groq_key
```

Required `config.json` entry:

```json
{
  "root_folder_id": "0Bz9C0ysJZ7PnMGZKeWcybUpXWGM"
}
```

> [!CAUTION]
> `.env` cannot be recovered from git. Use `.env.example` as the shape and fill in real secrets locally.

---

## Step 2 — Validate Mappings

Run the non-network sanity check before any Drive call:

```bash
python3 tools/validate_mappings.py
```

This verifies JSON schema versions, required fields, no duplicate folder IDs, and YAML consistency. Fix any errors before continuing.

---

## Step 3 — Rebuild the Mapping (if needed)

If mapping JSON files are missing or stale:

```bash
python3 tools/map.py build
python3 tools/rename_folders.py --create
```

If only some branches need refreshing:

```bash
python3 tools/map.py refresh --branch "Mechanical Engineering" --branch "Robotics and Automation"
python3 tools/rename_folders.py --create
```

---

## Step 4 — Sync All Files from Drive

Review which files need to be downloaded:

```bash
python3 tools/sync.py --files
```

Read `changelog/files.md`, then download:

```bash
# Recommended: rclone bulk download (fastest)
python3 tools/sync.py --files --apply --rclone --workers 8

# Alternative: Google Drive API
python3 tools/sync.py --files --apply

# Fallback if throttled:
python3 tools/sync.py --files --apply --gdown --download-delay 5
```

---

## Step 5 — Normalize Folders

```bash
python3 tools/rename_folders.py --dry-run
python3 tools/rename_folders.py
```

---

## Step 6 — Rename PDFs

Review:

```bash
python3 tools/rename_files.py --ocr-workers 1
```

Read `changelog/rename.md`, then apply:

```bash
python3 tools/rename_files.py --apply
```

---

## Step 7 — Verify and Move

```bash
python3 tools/verify.py
python3 tools/move.py
```

Check final state:

```bash
python3 tools/status.py --print
```

---

## Step 8 — Upload (if needed)

If `papers/` is intact and upload state needs to be rebuilt:

```bash
python3 tools/upload_pipeline.py preflight
python3 tools/upload_pipeline.py scan
python3 tools/upload_pipeline.py sync --workers 4
python3 tools/upload_pipeline.py manifest
python3 tools/upload_pipeline.py summary
```

---

## What Cannot Be Recovered from Git

| Item | Recovery |
|---|---|
| `.env` | Recreate from `.env.example` with real secrets |
| `tracking/*.db` | Regenerated by `sync.py --files --apply` |
| `incoming/` | Regenerated by `sync.py --files --apply` |
| `papers/` | Regenerated by `rename_files.py --apply` + `move.py` |
| `needs_review/` | Regenerated by `rename_files.py --apply` |
| `changelog/` | Regenerated by each review command |
| `manifest/*.json` | Regenerated by `upload_pipeline.py manifest` |

## What Survives a Clone

| Item | Status |
|---|---|
| `mapping/*.json` | Committed source — should survive |
| `mapping/folder_names.yml` | Committed source — should survive |
| `mapping/semester_mapping.yml` | Committed source — should survive |
| `mapping/local/` | Legacy runtime metadata — may legitimately be absent |
| `config.example.json` | Template — survives |
| `requirements.txt` | Committed — survives |
